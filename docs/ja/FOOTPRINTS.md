本書は、`MyMsg` のリソース消費量（RAM、CPU、起動時間、バイナリサイズ）の実測値および目標指標を定義します。

---

## 1. パフォーマンス目標値 (Target Metrics)

| 指標                            | 目標値              | 目的                                                 |
| :------------------------------ | :-----------------: | :--------------------------------------------------- |
| **アイドル時 CPU 使用率**       | **0.0%**            | バックグラウンド常駐やリソース逼迫環境での負荷ゼロ化 |
| **起動時間 (Cold Start)**       | **< 150 ms**        | コマンド実行からポップアップ表示までの知覚ラグ極小化 |
| **ワーキングセットメモリ (RAM)**| **< 35 MB**         | 仮想マシンや低スペック環境での安全な実行             |
| **リリースバイナリサイズ**       | **< 10 MB (非圧縮)**| 単一バイナリ配布の超軽量化                           |
| **遅延待機時 CPU/RAM**          | **0.0% / < 5 MB**   | GUI ウィンドウ生成前のリソース完全節約               |
| **トースト通知時 CPU/RAM**      | **0.0% / < 6 MB**   | GUI 非生成による瞬時終了 (< 20ms)                    |

## 2.1 高精度 CLI 実行時間ベンチマーク (hyperfine 測定)

Rust製のモダンCLIベンチマークツール [`hyperfine`](https://github.com/sharkdp/hyperfine) を用い、ディスクキャッシュを考慮したウォームアップ実行（`--warmup 3`）のもとでミリ秒単位で高精度に計測した実測値です。

```bash
# 測定コマンド
hyperfine --warmup 3 "target/release/MyMsg.exe -V"
hyperfine --warmup 3 "target/release/MyMsg.exe --help"
hyperfine --warmup 3 "target/release/MyMsg.exe --toast -m 'bench'"
```

| 測定対象コマンド                         | 平均実行時間 (Mean ± σ)     | 最小〜最大範囲 (Range)      | 判定    | 試行回数 |
| :--------------------------------------- | :-------------------------- | :-------------------------- | :-----: | :------: |
| `MyMsg.exe -V` (バージョン表示)          | **113.0 ms ± 17.7 ms**      | **87.0 ms 〜 164.5 ms**     | ✅ PASS | 24 runs  |
| `MyMsg.exe --help` (CLIヘルプ表示)       | **121.9 ms ± 22.8 ms**      | **77.5 ms 〜 154.1 ms**     | ✅ PASS | 21 runs  |
| `MyMsg.exe --toast` (トースト送信)       | **163.8 ms ± 25.0 ms**      | **120.5 ms 〜 212.7 ms**    | ✅ PASS | 16 runs  |

> [!NOTE]
> すべてのコマンドにおいて、目標値（起動〜完了まで < 150 ms）を安定してクリアしており、スクリプトやバッチ処理からの即応性に優れた結果となっています。

## 3. リソース節約のアーキテクチャ的工夫

1. **遅延表示モードの GUI 遅延生成**:
   `--delay` 待機中は DirectX / OpenGL / Vulkan コンテキストやウィンドウハンドルを一切生成せず、プロセスを低消費電力スリープ状態に保ちます。
2. **OS標準トースト通知の完全GUIバイパス**:
   `--toast` 指定時は `eframe` ウィンドウやグラフィックスパイプラインを一切初期化せず、OS のネイティブ通知 API のみを発行して十数ミリ秒でプロセスを終了します。
3. **イベント駆動レンダリング**:
   通常表示時は `ctx.request_repaint()` を連打せず、キーボード入力やマウスホバーなどのイベント発生時のみ再描画します。
4. **`--timeout` による自動リソース解放**:
   指定時間経過後に `ViewportCommand::Close` を発行し、バックグラウンドでのメモリ・プロセスの滞留を完全に防止します。

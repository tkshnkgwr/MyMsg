# MyMsg セキュリティ方針 (SECURITY)

本書は、`MyMsg` におけるセキュリティモデル、ローカル完結性、入力値の検証方針、および脆弱性報告プロセスを定めます。

---

## 1. セキュリティモデル & ローカル完結性

- **ネットワーク完全遮断 (Zero Network Access)**:
  `MyMsg` はネットワーク通信を行うクレートやコードを一切含みません。テレメトリ、アナリティクス、外部通信は存在せず、完全にローカル環境内で完結して動作します。
- **特権昇格なし (No Privilege Escalation)**:
  管理者権限（Administrator / root）を要求せず、一般的なユーザー権限で動作します。
- **安全なメモリ管理**:
  ビジネスロジックは Rust のセーフコードで記述されており、`unsafe` ブロックは Windows ネイティブ API 呼び出し（モニター列挙、セッション判定、通知音再生、メッセージポンプ処理）のみに厳格に局所化しています。

---

## 2. 入力値の検証と安全性

- **遅延時間・時間単位のガード (`clamp_delay_seconds`, `parse_duration_to_seconds`)**:
  `--delay` 引数は最大 86400 秒（24 時間）に制限されており、時間単位の乗算には `checked_mul` を用いて整数オーバーフローおよびプロセスの不正滞留を防止します。
- **フォントサイズの境界値ガード (`calculate_window_dimensions`)**:
  `--font-size` に `NaN`・`Infinity`・0以下の値が渡された場合はプリセット既定値へフォールバックし、極端な値は安全な範囲（8.0pt〜200.0pt）にクランプします。
- **不正なカラー文字列・マルチバイト入力の安全なフォールバック (`parse_color`)**:
  未定義のカラー名や構文異常の HEX コード、非 ASCII マルチバイト文字列が指定された場合でもパニックせず、デフォルト色に安全にフォールバックします。
- **安全なファイル読み込み**:
  フォント読み込み処理では、ファイルが存在しない場合やパーミッションエラー時も安全に無視され、フォールバックフォントで起動します。

---

## 3. 脆弱性の報告手順

`MyMsg` においてセキュリティ上の脆弱性を発見された場合は、公開 Issue ではなく以下の手順でご報告ください：

1. GitHub リポジトリの **Security Advisories**（非公開報告機能）からレポートを作成してください。
2. 担当者が 48 時間以内に内容を確認し、修正計画をご連絡いたします。

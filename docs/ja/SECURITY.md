# MyMsg セキュリティ方針 (SECURITY)

本書は、`MyMsg` におけるセキュリティモデル、ローカル完結性、入力値の検証方針、および脆弱性報告プロセスを定めます。

---

## 1. セキュリティモデル & ローカル完結性

- **ネットワーク完全遮断 (Zero Network Access)**:
  `MyMsg` はネットワーク通信を行うクレートやコードを一切含みません。テレメトリ、アナリティクス、外部通信は存在せず、完全にローカル環境内で完結して動作します。
- **特権昇格なし (No Privilege Escalation)**:
  管理者権限（Administrator / root）を要求せず、一般的なユーザー権限で動作します。
- **安全なメモリ管理**:
  100% Rust のセーフコードで記述されており、メモリ破壊やバッファオーバーフローのリスクを極小化しています。

---

## 2. 入力値の検証と安全性

- **遅延時間のガード (`clamp_delay_seconds`)**:
  `--delay` 引数は最大 3600 秒（1 時間）に制限されており、極端に大きな数値によるプロセスの不正滞留を防止します。
- **不正なカラー文字列の安全なフォールバック**:
  未定義のカラー名や構文異常の HEX コードが指定された場合でもパニックせず、デフォルト色に安全にフォールバックします。
- **安全なファイル読み込み**:
  フォント読み込み処理では、ファイルが存在しない場合やパーミッションエラー時も安全に無視され、フォールバックフォントで起動します。

---

## 3. 脆弱性の報告手順

`MyMsg` においてセキュリティ上の脆弱性を発見された場合は、公開 Issue ではなく以下の手順でご報告ください：

1. GitHub リポジトリの **Security Advisories**（非公開報告機能）からレポートを作成してください。
2. 担当者が 48 時間以内に内容を確認し、修正計画をご連絡いたします。
